Technical architecture

TrendScope AI

Version 1.0 Date 7 November 2026 Market Australia · AUD Status Proposed for Phase 1

A product intelligence platform whose numbers have to survive scrutiny. The architecture is shaped less by feature count than by three rules: never present an estimate as a sale, never let a missing measurement read as a decline, and never let one dead provider stop a run.

The repository is empty. This is a greenfield build against the PRD's prescribed stack (Next.js, FastAPI, PostgreSQL, Celery, Redis, Docker Compose), with the additions needed to keep scores explainable and historical data intact.

ConstraintsWhat the data landscape forces

Four of the PRD's providers cannot be integrated the way the document assumes. The product is designed for that rather than around it.

Google Trends
Paid intermediary

No public API. The official one is application-only alpha; pytrends was archived in April 2025. Phase 1 uses DataForSEO behind the connector interface, roughly US$38–165/month depending on cadence.

Amazon AU
Mock only

PA-API 5.0 is being retired, has no bestseller endpoint, and no amazon.com.au domain. Keepa has no AU catalogue. There is no first-party route, so Amazon stays mock until a licensed vendor clears legal review.

TikTok
Blocked

No public Creative Center API, the internal endpoint broke in October 2026, and the official Commercial Content API covers only EU/EEA/UK/CH. Social momentum is unavailable in Australia for now.

eBay AU
Listings only

Browse API returns active listings, which covers competition and price. Sold data went with the Finding API in February 2025, and Marketplace Insights is closed to new users. The UI says "active listings", never "sales".

Exploding Topics
CSV first

The API exists but needs a US$249 plan plus at least US$1,000/month for 1,000 requests. CSV export is available on the US$99 plan, so Phase 2 imports files rather than paying for calls.

01Two paths, one database

Reads and writes never share a route. Nightly ingestion appends raw observations for one provider at a time. A daily derive job turns those observations into dated snapshots. Every API request reads only the snapshots.

Three boundaries carry most of the design. Raw observations and derived values are separate tables, so scores can be recomputed without touching evidence. Providers are isolated behind a lock and a circuit breaker, so a failing API degrades one source rather than the pipeline. Synthetically generated data is flagged at the observation level and travels into every score, so a demo cannot be mistaken for market data.

04Backend layers

Dependencies point one way. A router may call a service; a service may call repositories and connectors; a connector may not import models or settings. Domain rules live in services and are pure functions where possible, which is what makes the scoring and GST tests exhaustive instead of illustrative.

ModuleResponsibility
api/v1Validate input, call one service, return a schema. Roughly fifteen lines per handler.
servicesBusiness rules. Scoring, growth, competition and profitability are pure and DB-free.
repositoriesQuery construction, filters, pagination. No HTTP, no scoring.
connectorsProvider adapters. Receive credentials in a context object; never read settings or the database.
pipelineStages with explicit transaction boundaries and idempotency keys.
jobsCelery tasks that call services. No domain logic of their own.

05Connector framework

Every provider implements the same three methods. A connector returns observations, never scores, so switching from one Trends vendor to another is a new class and a new registry key, not a pipeline change.

class Connector(Protocol):
    provider_key: ClassVar[str]
    source_type: ClassVar[SourceType]

    async def health_check(self, ctx) -> HealthResult: ...
    async def discover(self, ctx, query) -> AsyncIterator[ProductCandidate]: ...
    async def fetch(self, ctx, targets, window) -> AsyncIterator[ObservationBatch]: ...

Credential handling

Secrets exist only as environment variables. data_sources.secret_ref stores the variable names, so the admin screen can say which are missing without ever serialising a value.

Failure handling

Retries with exponential backoff and jitter apply to 429 and 5xx only. Auth failures stop immediately with an actionable message. A circuit breaker skips a repeatedly failing provider and marks it degraded.

Per-provider lifecycle

  • Enable or disable without deleting history. The source row stays, the scheduler skips it.
  • Rate limit with a Redis token bucket sized per provider, not per process.
  • Incremental sync using the stored cursor where a provider supports it; otherwise re-fetch the window and upsert on the natural key.
  • Run bookkeeping in ingestion_runs: fetched, written, rejected, errors, cursor, timestamps.
  • Raw payload retention for 90 days in source_records, enough to debug or replay an ingestion.
  • Synthetic labelling at the source row, denormalised onto every observation and score it produces.

07Growth rules

Growth compares two complete windows, ending yesterday. Today is excluded so a partial day never reads as a collapse. The formula is the PRD's:

growth_pct = (mean(current_window) / mean(previous_window) - 1) × 100

Each window must contain at least 70% of its days. When it cannot be computed honestly, the value is null with a reason code, never zero.

ConditionStored result
Fewer than 5 of 7 days in either windownull · insufficient_current_data
Baseline mean below 5.0 index pointsnull · insufficient_baseline
Baseline mean is exactly zeronull · zero_baseline
Latest observation older than 3 daysnull · stale_data
Computed growth above 900%Raw value kept · extreme_growth flag

Trends values are normalised per request window, so the connector records the window it asked for. Growth is only computed inside a consistently scaled series, which is the subtlest correctness trap in the system and gets its own test.

Competition

Active listing count, Australian retailer count, price dispersion, review concentration (HHI over the top ten listings) and brand dominance each normalise to 0–100. Fewer than two available inputs yields unknown, not "low": a thin index is not evidence of an open market.

08Scoring

Six components, one hundred points, and a rule that missing evidence is excluded rather than scored zero.

ComponentWeightBasis
Demand25%30-day growth, 7-day momentum, index level
Marketplace25%Listing count, review velocity, rank movement
Social15%Engagement and hashtag views
Competition15%100 minus the competition index
Profitability15%Contribution margin at the reference price
Seasonal5%Seasonality index over the next 90 days

Bars are scaled to the largest weight, not to 100 points.

weight_available = Σ wᵢ            components with usable evidence
score_raw        = Σ (wᵢ × sᵢ) / weight_available
confidence       = coverage × freshness × sample × source diversity
score            = 50 + (score_raw − 50) × confidence

Renormalising weights alone would let one perfect component turn 25% of the evidence into a score of 100. Shrinking toward 50 by confidence keeps the ranking honest, and both values are stored.

Classification

80–100 excellent, 65–79 strong, 50–64 worth investigating, 35–49 weak, 0–34 low priority. Below 60% coverage the classification becomes insufficient_data regardless of the number, and the UI shows "not enough data to rank" instead of a badge. Every score row stores its component scores, raw inputs, weights snapshot and coverage, so any ranking can be explained a year later.

09Profit and GST

The calculator is a pure function over decimals, tested against worked examples to the cent.

  • Consumer prices are GST-inclusive, so price_ex_gst = price_inc_gst / 1.1.
  • When the supplier charges Australian GST and the business is registered, that GST is an input tax credit. It is excluded from the economic cost and still shown in the cash landed cost.
  • Import duty is a real cost, not recoverable, and is configurable per scenario.
  • Payment fees apply to the GST-inclusive amount. Contribution margin is measured after fees, fulfilment, packaging and acquisition cost.
  • Outputs include break-even ad cost and profit at 100, 500, 1,000 and 5,000 orders per month.

10AI layer

Phase 4, but the interface is fixed now so the retrieval surface exists before the model does. The assistant reaches data only through tools that wrap the same services the API uses: search products, read a series, compare products, read competition, list suppliers, calculate profit, read a report.

Answers are structured claims, not prose alone. Each claim carries an evidence type: verified, estimated, model_generated or unavailable. A verified claim must resolve to a stored observation, score or report id; the validator rejects an answer that cites nothing. Product titles arriving from a provider are treated as data, never as instructions.
